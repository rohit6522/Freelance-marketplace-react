1. Introduction

GigCraft is a comprehensive, production-grade freelance marketplace web application engineered to bridge skilled technical freelancers with startup founders, businesses, and engineering managers across India. The application provides an interactive service discovery catalogue, dynamic multi-tier package selection, an end-to-end contract milestone lifecycle, in-app messaging, responsive dashboards, and verified client review mechanisms.

1.1 Purpose

The purpose of this Software Requirements Specification (SRS) is to establish a rigorous, clear, and unambiguous technical definition of the functional, non-functional, interface, and data modeling requirements for GigCraft. It serves as an authoritative reference for project developers, academic evaluators, testers, and reviewers assessing the application's architecture and capabilities.

1.2 Scope

The product is named GigCraft. It is constructed on a modern full-stack architecture leveraging React 19, Tailwind CSS, Node.js, Express.js, and MongoDB Atlas with Mongoose.

The system is specifically engineered to:

  • Present an open service catalogue enabling clients to discover verified technical and creative gigs.
  • Provide multi-parameter filtering across service categories, budget limits (in Indian Rupees ₹), turnaround delivery days, seller tiers, and review score thresholds.
  • Detail standardized 3-tier package structures (Basic, Standard, Premium) with transparent feature inclusions and turnaround deadlines.
  • Manage order lifecycles through clear state transitions (Pending, In Progress, Delivered, Revision Requested, Completed, Cancelled).
  • Provide direct in-app messaging between buyers and sellers with attachment support.
  • Supply customized dashboards for clients (spending pipeline, active contracts) and freelancers (milestone progress, monthly performance charts, portfolio management).
Academic Non-Revenue Note: GigCraft is developed for educational and portfolio demonstration. In accordance with project requirements, the system does not integrate real-world banking merchant accounts, actual monetary payments, or commercial GST invoicing. All financial transactions and order states operate via simulated internal contract workflows.

2. General Description

2.1 Product Perspective

GigCraft operates as an independent two-sided marketplace web application. The frontend client is implemented as a single-page application (SPA) with React 19, styled using Tailwind CSS v4, and structured around client-side routing. The backend is an asynchronous REST API built with Node.js and Express.js, connecting to a managed MongoDB Atlas cluster via Mongoose ODM.

2.2 Product Functions

2.3 User Characteristics

  • Client (Buyer): Discovers service offerings, initiates orders with project requirements, inspects submitted deliverables, requests revision cycles, and rates freelancers.
  • Freelancer (Seller): Authors gigs with tiered pricing, sets delivery turnaround expectations, delivers files, and manages public profiles and portfolios.
  • System Administrator / Evaluator: Audits data integrity, monitors database collections, and verifies order milestone transitions.

2.4 General Constraints

  • The web interface requires modern standards-compliant web browsers supporting ES2022 and modern CSS layouts.
  • Database persistence is dependent on valid MongoDB connection strings and cloud connectivity.
  • Authentication utilizes cryptographically signed JWTs stored in secure HTTP-only cookies.
  • All financial values are strictly simulated internally to support academic educational goals without monetary liability.
  • Uploaded media and deliverable files must observe a maximum per-file ceiling of 25 MB across approved file extensions.

2.5 Assumptions and Dependencies

  • Freelancer profiles and sample gigs are initialized via the database seed script to provide realistic evaluation data.
  • MongoDB Atlas remains accessible and responsive via the configured connection string.
  • All user timestamps are recorded in UTC in the database and formatted into Indian Standard Time (IST) on display.

3. Specific Requirements

3.1 External Interface Requirements

3.1.1 User Interfaces

  • Marketplace Exploration: Responsive grid interface showing gig cards, starting prices in ₹ INR, seller tier badges, and live filter toggles.
  • Gig Detail Page: Comprehensive view comparing Basic, Standard, and Premium packages, deliverable features, turnaround days, and FAQs.
  • Order Placement Modal: Interactive dialog for clients to supply project briefs and optional attachment files with immediate package price summaries.
  • Contract Operations Console: Dual-pane interface displaying the contract ledger on the left and full milestone timelines, delivery files, and messaging on the right.
  • Seller & Client Dashboards: High-level KPI summary cards displaying active pipeline counts, completed jobs, and monthly performance charts.

3.1.2 Hardware Interfaces

No specialized hardware interface is required. The platform is accessible via standard client devices (desktops, laptops, tablets, smartphones) equipped with modern web browsers and an active internet connection.

Client-server communication is carried over HTTP/HTTPS with JSON-encoded request and response bodies. Authenticated sessions utilize secure, HTTP-only, SameSite=Lax cookies.

3.2 Functional Requirements

3.2.1 Service Marketplace Catalogue and Filtering

3.2.1.1 Introduction: Enables visitors to browse the service catalogue and apply multi-parameter filters.

3.2.1.2 Inputs: Query string, category slug, price boundaries (minPrice, maxPrice in ₹ INR), delivery deadline, seller tier, and sort mode.

3.2.1.3 Processing: The Express route handler builds a dynamic Mongoose aggregation pipeline executing text searches, category filters, and price ranges against published gigs.

3.2.1.4 Outputs: Paginated array of matching gig cards with seller metadata, ratings, and starting prices.

3.2.1.5 Error Handling: Returns HTTP 400 for malformed parameters and an empty state card when zero gigs match the query.

3.2.2 Gig Detail, Multi-Tier Packages and Specification

3.2.2.1 Introduction: Presents full gig deliverables, image galleries, and side-by-side package tiers.

3.2.2.2 Inputs: Gig ID parameter.

3.2.2.3 Processing: Populates the gig document with seller profile, review counts, average score, and category records.

3.2.2.4 Outputs: Structured gig specification showing Basic, Standard, and Premium pricing, turnaround days, included features, and reviewer comments.

3.2.2.5 Error Handling: Invalid or missing IDs return HTTP 404 with a safe fallback link to the marketplace.

3.2.3 Order Lifecycle, Milestones, and Work Submissions

3.2.3.1 Introduction: Coordinates project contracting from order creation to final delivery approval.

3.2.3.2 Inputs: Gig ID, package tier, requirement text (minimum 20 characters), and optional brief files.

3.2.3.3 Processing: Snapshots package deliverables and price, generates a unique order number (e.g., GC-8B41D9), sets initial status to pending, and manages state transitions to in_progress, delivered, revision_requested, and completed.

3.2.3.4 Outputs: Order contract record, milestone progress timeline, and delivery package files.

3.2.3.5 Error Handling: Non-participants cannot view order data (HTTP 403/404); invalid transitions return HTTP 409 Conflict.

3.2.4 Real-Time In-App Messaging & Threaded Communication

3.2.4.1 Introduction: Facilitates project communication directly between order participants.

3.2.4.2 Inputs: Conversation ID, text body, and optional attachment files.

3.2.4.3 Processing: Verifies user authorization, appends message to the database, updates conversation activity, and increments unread indicators for the counterparty.

3.2.4.4 Outputs: Chronologically sorted message stream with user avatars, timestamps in IST, and file downloads.

3.2.4.5 Error Handling: Rejects unauthorized access attempts and empty message submissions.

3.2.5 User Authentication & Profile Management

3.2.5.1 Introduction: Governs user registration, credential verification, and profile management.

3.2.5.2 Inputs: First name, last name, email, password, role (Client or Freelancer), phone (+91 format), and profile bio.

3.2.5.3 Processing: Hashes password using bcrypt with 12 rounds, creates User and FreelancerProfile documents, and signs an HTTP-only JWT cookie.

3.2.5.4 Outputs: User profile object, secure session cookie, and role-specific workspace navigation.

3.2.5.5 Error Handling: Duplicate emails return HTTP 409; invalid credentials return HTTP 401.

3.2.6 Seller Dashboard, Performance Analytics & Reviews

3.2.6.1 Introduction: Provides metrics on active contracts, earnings history, and client feedback.

3.2.6.2 Inputs: Authenticated user session.

3.2.6.3 Processing: Aggregates order collections by status, calculates simulated commitment totals, and builds monthly performance arrays.

3.2.6.4 Outputs: Metric cards, recent orders table, 6-month earnings visual chart, and verified review logs.

3.2.6.5 Error Handling: Unauthorized role access attempts are intercepted and redirected.

3.5 Non-Functional Requirements

3.5.1 Performance

  • The catalogue and gig views render under 1.5 seconds under normal broadband connections.
  • Database queries utilize compound indexes on { status: 1, category: 1, startingPrice: 1 } and text indexes for sub-50ms search lookups.
  • Vite client bundling achieves optimized tree-shaking and minification for rapid initial asset delivery.

3.5.2 Reliability

  • Package details are permanently snapshotted into order records upon purchase, ensuring subsequent gig edits never corrupt existing contracts.
  • Frontend error handling displays inline retry banners (ErrorBox) to prevent application crashes.

3.5.3 Availability

  • The application architecture supports continuous cloud hosting on platforms such as Vercel and Render with automated reconnects to MongoDB Atlas.

3.5.4 Security

  • Passwords are encrypted with bcrypt using 12 salt rounds; plain-text passwords are never stored.
  • JWT tokens are stored exclusively in HTTP-only, SameSite=Lax cookies to prevent client-side script interception.
  • Rate limiting restricts brute-force attempts on sensitive endpoints to 20 requests per 15 minutes.

3.5.5 Maintainability

  • Strict modular structure separating UI components, hooks, service layers, Express controllers, and Mongoose schemas.
  • Centralized formatting utilities in format.js eliminate duplicate localization logic.

3.5.6 Portability

  • Responsive layout designed with Tailwind CSS functions consistently across mobile, tablet, and desktop form factors.
  • Configuration relies entirely on environment variables, allowing the application to deploy across any Node.js environment.

3.7 Design Constraints

  • Built entirely in JavaScript (ES Modules) across both React 19 and Node.js tiers.
  • Persistence is strictly managed with MongoDB document schemas using Mongoose ODM.
  • Non-commercial academic scope: real payment gateways, banking transactions, and tax validation are intentionally omitted.

3.9 Other Requirements

  • The database seed script provides authentic Indian freelancer profiles, INR package costs, and verified test orders for review.
  • All dates and numbers adhere to Indian formatting conventions (IST and en-IN lakh/crore grouping).

4.1.3 Main Data Stores

  • User Store (users): User identity, hashed passwords, roles, company name, and phone (+91 format).
  • Freelancer Profile Store (freelancerprofiles): Professional titles, bios, Indian locations, skills, languages, and rating metrics.
  • Gig Store (gigs): Service titles, category links, tags, multi-tier pricing (Basic, Standard, Premium), and cover galleries.
  • Order Store (orders): Unique order numbers, participant references, requirement briefs, package snapshots, deliverables, and milestone history.
  • Payment Store (payments): Internal simulated commitment records tracking status (held, released, refunded) in INR.
  • Conversation & Message Store (conversations, messages): Conversation bindings, unread tracking, message bodies, and attachments.
  • Review Store (reviews): Post-delivery star ratings (1–5), detailed feedback, and freelancer replies.
